# ResetSelf MVP 开发计划

## 1. 目标

本计划对齐以下两份产品文档：

- `ResetSelf APP｜分级开发迭代任务清单（可直接排期落地）.md`
- `重身ResetSelf APP 完整产品与设计架构文档.md`

MVP 的目标不是做一个完整的“成长类工具”，而是先跑通一条最小可用闭环：

`入驻 -> 首次重构 -> 首页身份卡 -> 每日校验 -> 样本沉淀`

在此基础上，再继续扩展 SOS、洞察、年度归档和报告能力。

## 2. 产品边界

### 2.1 本期必须做

- Flutter Android 主工程
- SQLite 本地持久化
- 首次重构流程锁
- 首次重构 5 步向导
- 首页身份卡与最小行动
- 每日三态校验
- 偏差样本入库
- SOS 急救入口
- 惯性样本库基础展示

### 2.2 本期不做

- 排行、勋章、连续打卡
- 社区、信息流、分享裂变
- 商业化付费系统
- 云同步
- 年度白皮书最终版导出

## 3. 迭代原则

- 先 `P0 可用`，再 `P1 壁垒`，最后 `P2 稳定商业化`
- 所有核心数据优先本地落 SQLite
- 所有关键流程必须支持断点保存与离线可用
- 未完成首次重构前，必须锁定首页、校验、SOS、洞察
- 体验层坚持无挫败原则，不使用红色惩罚反馈

## 4. 技术基线

- 前端框架：Flutter
- 状态管理：Riverpod
- 路由：GoRouter
- 本地数据库：SQLite（当前接入 `sqflite`）
- 运行平台：Android 优先

## 5. 阶段计划

### 5.1 P0 核心兜底

目标：项目能跑通、数据不丢失、流程不崩坏。

#### P0-1 工程与数据基建

- 初始化 Flutter Android 主工程
- 建立应用主题、路由、基础目录结构
- 建立 SQLite 6 张核心表
- 建立 Repository 层与事务写入能力
- 建立首次启动初始化逻辑

交付结果：

- 工程可启动
- SQLite 可正常建表
- 首次启动存在默认用户主记录

#### P0-2 流程锁与应用状态

- 建立全局 `app state`
- 建立引导页、首次重构页、首页、校验页、洞察页、设置页、SOS 页的路由
- 未完成首次重构前，只允许访问引导页与首次重构向导
- 完成首次重构后自动跳转首页

交付结果：

- 路由守卫生效
- 首次重构前后状态切换正确

#### P0-3 首次重构主链路

- 实现 5 步向导：
  - 反愿景
  - 底层恐惧
  - 限制性信念
  - 新身份叙事
  - 极简行动
- 实现输入中的软提示
- 每步数据自动保存草稿
- 最终提交时写入用户主档、重构记录、限制性信念

交付结果：

- 用户可完整完成首次重构
- 重构结果可回填首页

#### P0-4 首页与每日校验闭环

- 首页展示身份宣言
- 首页展示明日最小行动
- 首页展示今日校验入口
- 每日校验支持三态：
  - 完全匹配
  - 部分偏离
  - 完全偏离
- 每次校验写入 `daily_checkin`
- 偏离或样本事件写入 `inertia_sample`

交付结果：

- 首页可读真实数据
- 校验完成后能写库并返回首页

#### P0-5 SOS 与样本库基础版

- 首页悬浮 SOS 按钮
- SOS 页面支持快速标签选择
- SOS 选择写入 `inertia_sample`
- 洞察页展示最近 7 天惯性样本

交付结果：

- 样本库不再是静态数据
- SOS 形成“记录 -> 入库 -> 回首页”闭环

### 5.2 P1 产品壁垒

目标：落地“认知真空”和长期低压力使用体验。

- 极简模式与认知真空能力接入
- 每周复盘 SQL 聚合
- 中性归因文案引擎
- 首页与洞察页动画、空态、错误态
- 历史重构记录归档

### 5.3 P2 稳定商业化

目标：支持长期沉淀、归档回顾和导出能力。

- 年度归档
- 年度变化报告
- 数据导出/备份
- 发布与升级策略

## 6. 周期建议

### 第 1 周

- 完成数据基建
- 完成路由与流程锁

### 第 2 周

- 完成首次重构 5 步向导
- 完成自动保存与最终提交

### 第 3 周

- 完成首页
- 完成每日校验
- 完成样本入库

### 第 4 周

- 完成 SOS
- 完成样本库真实列表
- 完成 P0 验收与问题修复

## 7. P0 验收标准

- 应用首次启动后可以进入引导页
- 未完成首次重构前无法进入首页、洞察、SOS
- 首次重构完成后首页展示真实身份与最小行动
- 每日校验能写入数据库
- SOS 能写入样本库
- 重新打开应用后数据不丢
- 无网络下仍可完成核心流程

## 8. 风险与依赖

- Android 首次构建依赖 Gradle 下载，需代理稳定
- SQLite 数据结构一旦变更，需要同步设计迁移策略
- 原型视觉已定，后续页面新增需保持同一设计系统
- 向导输入自动保存若实现不当，容易造成状态污染或重复提交

## 9. 当前建议的下一步

按优先级继续推进以下事项：

1. 将首次重构 5 步的输入真实写入 SQLite
2. 将每日校验三态真实写入 `daily_checkin`
3. 将 SOS 选择真实写入 `inertia_sample`
4. 将洞察页改为读取 SQLite 真数据
5. 将首页身份卡与最小行动完全改为数据库驱动
