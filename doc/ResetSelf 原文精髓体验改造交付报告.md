## 1. 已实现的用户路径

晨间保留 14 问原稿；日间能带回晨稿，并用实际行为核对解释；晚间回看所选日期范围内的观察，整理六组件及行动与边界。首页能取得月项目与方向，用户可以主动修改最小启动行动。反馈提示比较期望与实际，保存下一次调整，并提供修改行动和方向的入口。

第四轮补齐晚间步骤恢复、晨间待回看标记、可选修改原因和多批次晨稿归档。重构中枢的“重新做一次身份重构”提供“归档原稿，开始新探索”；“晨间原稿归档”可查看历史正文、标记及日期范围内的观察，并恢复旧稿；“行动修改历史”展示前后文本和可选原因。

保留原文内部模式、自我保护和身份探索的锋利提问；补充“待核对的解释”和现实条件提示。没有用回答次数、停留时间或完成专注推断心理改变。六组件、身份、每日杠杆、最小启动行动、价值约束与环境规则继续分别表达。

## 2. 历史问题与实施对应

| 历史问题／方案任务 | 当前处理 | 证据位置 |
|---|---|---|
| 反馈首次输入仍不能保存 | 每次输入更新按钮；清空禁用；失败保留；保存中禁编辑及重复提交 | `action_feedback_page.dart`、组件回归 |
| 草稿退出和异步竞态 | 不可变快照顺序写入；返回及系统返回等待；后台切换尝试保存；失败可重试／继续／明确放弃 | `draft_save_controller.dart`、`draft_navigation_guard.dart`、组件回归 |
| 必要写入失败仍算提交完成 | 正式方向、身份库、当前身份、年度记录与草稿清理纳入事务 | 仓库提交方法、真实 SQLite 故障回滚测试 |
| 状态通知重建路由／提交失败跳启动页 | 保留路由实例；只对初始化失败跳启动页；提交错误留在编辑页 | `app_router.dart`、`app_controller.dart`、路由回归 |
| 日间关闭通知隐藏练习 | 开关仅用于通知；手动表单仍可写；分类可选，默认保存为“未归类” | 日间页与组件回归 |
| 切题丢掉尚未提交文字 | 本页按问题缓存文字与分类，保存期间禁切换 | 日间页 |
| 日间材料缺提问上下文 | 新记录保存问题 id／题干；旧记录明确“未记录问题” | SQLite v12、观察模型、回顾页 |
| 晚间只回顾今天 | 默认从当前晨稿开始日到今天；显示范围并可更改 | `exploration_review_sheet.dart`、日期查询及回顾测试 |
| 行动与项目断开 | 首页行动附近可展开月项目及完整方向；明确用户操作才能修改行动 | `direction_summary.dart`、`min_action_editor.dart` |
| 新方向误解释旧反馈 | 开始编辑时固定可用方向；随记录保存快照，历史注明当时参考的方向 | 反馈页、方向变化回归、备份测试 |
| 历史方向缺完整六组件 | 历史卡可展开全部组件和额外字段 | 重构中枢 |
| 方法来源、适配与边界不清 | 引导页与中枢提供作者、文章链接与复制入口；说明跨日、数字记录及扩展 | `method_note.dart` |
| 周／年统计、空状态和提醒越界 | 改述记录事实；无记录不等于无偏离；不承诺所有设备准时 | 文案引擎、统计页、年度报告及 Android 提醒 |
| 错误被显示为空列表 | 晨间、反馈、观察与材料回顾区分读取失败和空记录，提供重试 | 对应页面 |
| 晚间重新进入总从第一步开始 | 保存步骤 id；前进、后退及退出沿用顺序保存，未知旧值回到首步 | 草稿模型、晚间页、组件及 Android 回归 |
| 问题答不出但需要回来想 | 待回看标记可独立保存；晚间回顾和历史原稿显示标记，空回答也保留 | 晨间页、材料回顾、标记恢复测试 |
| 修改行动和方向缺少原因 | 原因可选；行动变化事务记录前后文本，方向原因随提交归档 | 行动编辑、方向摘要、仓库和备份回归 |
| 开始新探索覆盖旧晨稿 | 独立归档回答、标记及时间；恢复先归档当前稿，原历史继续保留 | 重启弹层、晨稿历史、SQLite 故障回滚及 Android 流程 |

专属“再次尝试”按钮、六组件同屏、独立理论页和观察批次外键不作为方法硬要求。第四轮便利功能已根据用户的继续指令实施；这些能力服务于保存、比较与自主调整的路径，不增加强制问卷。

## 3. 数据与兼容

前三轮 SQLite 从 v11 升级到 v12：

- `inertia_sample.prompt_id`、`prompt_snapshot`：可空问题上下文。
- `action_feedback.direction_snapshot`：可空方向上下文。
- `exploration_state`：一份当前探索的开始时间元数据，无原稿时可以没有此行。

第四轮升级到 v13：

- `exploration_state.review_question_keys`：待回看问题，默认空 JSON 数组。
- `restructure_draft.current_step_id`、`change_reason`：步骤默认 `anti`，原因默认空文本。
- `restructure_record.change_reason`：可空方向修改原因；旧记录不补造解释。
- `morning_archive`：每份原稿的回答、标记和开始／归档时间。
- `action_change`：行动前后文本、时间和可选原因，仅文本实际变化时写入。

开始新探索或恢复历史稿前明确提示：当前晨稿及标记归档，未提交晚间草稿将清除；已保存方向、观察和反馈保留。归档、替换和清理在同一事务中执行，任何写入失败均保留当前稿和晚间草稿。恢复旧稿使用复制，不删除历史版本；空稿且无标记时不创建空归档。

新字段与新表加入导出、清理及恢复流程。旧备份缺上下文及元数据时保留正文，恢复为缺上下文；不把旧记录绑定到当前方向。

迁移测试以真实 SQLite 临时文件重建 v1–v12 的版本差异，再通过生产 `onUpgrade` 升到 v13。包含 v6 新安装曾遗漏 `current_anchor_id` 的情况；这是版本结构夹具测试，不宣称持有并验证所有历史设备数据库副本。

日期查询使用本地自然日半开边界，兼容 ISO 时区偏移和旧 SQLite 时间文本；非法时间不冒充今天。晨稿开始时间在后续修改中保持稳定，明确清空原稿才清除元数据。

## 5. 验证边界与后续

当前检测到 Android 17／API 37 的 x86_64 模拟器，没有连接物理手机。通知权限变化、真实到点送达、省电策略、重启后提醒，以及通知冷／热启动直达仍需物理设备验收。本次不将源码存在或 APK 可构建写成这些场景已通过。

晨间保留一份当前原稿和多份独立历史归档；日期范围不自动证明观察属于某个唯一批次。旧数据没有步骤时从首步继续，没有原因时不编造原因。日间切题缓存只在本页有效，日间与反馈离开前需主动保存。草稿后台切换尽可能落库，操作系统强制结束前尚未落库的文字无法保证恢复。

第四轮四项便利功能已实现并验证。用户体验验证仍应观察真实使用者能否找到材料、自主解释、形成行动并从反馈中调整；本次工程验证不证明“一天改变人生”的效果。
