## 1. 文档地位与来源规则

### 1.1 基础来源

本规范依据仓库中的 [《How to fix your entire life in 1 day》中英对照](./How-to-fix-your-entire-life-in-1-day_中英对照.md)。来源文件标注作者为 Dan Koe，原文链接为 https://x.com/thedankoe/status/2010751592346030461 。

本次依据本地文本进行对齐，未重新核验远端文章版本。英文段落作为语义核对依据，中文作为项目表达参考；出现歧义时应记录对应英文、中文及解释理由。原文中的修辞、案例和作者判断，应保留其性质，不能自动升级为已验证的普遍规律。

### 1.2 文档使用顺序

1. 原文用于判断作者说了什么。
2. 本规范用于判断 ResetSelf 如何采用、适配或扩展这些内容。
3. 产品设计和开发任务用于描述具体功能与交互。
4. 当前代码与运行验证用于判断已经实现什么。

历史设计文档中与本规范冲突的方法定义和效果表述，以本规范为准。历史文档不作为原文要求或当前功能已完成的证明。用户已确认的界面与产品偏好仍是产品约定，不因来源重新分类而自动取消。

### 1.3 四类来源标记

| 标记 | 含义 | 使用规则 |
|---|---|---|
| 原文原则 | 作者明确提出的观点或方法逻辑 | 必须给出原文章节；介绍观点时使用“作者提出”“本文采用” |
| 原文建议／示例 | 作者建议的流程、数量、时长或举例 | 保留建议性质，不擅自变成不可跳过的硬规则 |
| 产品适配 | 为数字应用、低负担体验或当前版本作出的转换与简化 | 明确原文是什么、产品改了什么、可能损失什么 |
| 产品扩展 | 原文未直接规定，ResetSelf 自行增加的机制 | 说明用途；不得称为“Dan Koe 原版规定” |

同一功能可以同时包含多类来源。例如：日间追问来自原文；六个示例时间来自原文建议；固定每日排程是产品适配；Android 常驻服务是工程实现。

本规范中的“必须”“不得”是 ResetSelf 的方法与文案规则，不能据此宣称作者设定了相同禁令。

## 3. 统一方法定位

### 3.1 对外定位

采用以下表述：

> ResetSelf 是一款基于 Dan Koe 一日反思流程设计的自省与行动校准工具。它帮助用户探索行为背后的动机，明确想要的生活，组织目标与行动，并通过记录和回顾持续调整。

产品的作用是支持思考、行动和反馈。用户的选择与实践是改变的主体。

### 3.2 核心原则

| 编号 | 统一定义 | 来源与边界 |
|---|---|---|
| M1 | 同时关注想成为的人、相应生活方式和具体行动 | 原文原则，S1；身份优先不等于行为无效 |
| M2 | 从实际行为探索它正在服务的目标或需求 | 原文原则，S2；具体归因仍需用户观察与核对 |
| M3 | 检视旧身份及其防御，并允许新身份继续变化 | 原文原则，S3、S4；身份陈述不是永久标签 |
| M4 | 将目标作为组织注意力和选择的可调整镜头 | 原文原则，S2、S7；目标可以包含具体成果或数值 |
| M5 | 将反愿景的觉察导向愿景与建设性行动 | 原文原则，S6；不把厌恶自己或强烈痛苦作为产品验收条件 |
| M6 | 通过行动、观察、比较和调整形成反馈循环 | 原文原则，S5；记录次数本身不等于进步 |
| M7 | 用六组件组织方向、项目、行动和边界 | 原文原则，S8；行动应解释其与项目的关系 |
| M8 | 用低负担、无羞辱、无攀比的体验支持继续实践 | 产品扩展；不承诺消除焦虑、挫败或反弹 |

### 3.3 身份、目标和行动之间的关系

身份陈述表达“我希望以怎样的方式生活和行动”；目标镜头表达“这一阶段希望什么事实发生”；行动表达“我现在具体做什么”。

三者应相互支持，也应根据经验共同调整。不得将“先改身份、后改行为”解释为必须先完成心理改变才能行动，或将先尝试行动的人判定为必然反弹。原文在身份形成循环中也包含目标、行动与反馈。

“身份固化”统一解释为：通过重复实践形成更稳定的行为倾向，同时保留反思和修改身份陈述的空间。它不表示一次填写就能永久改写潜意识。

### 3.4 隐藏目标、内在模式和现实条件

“隐藏目标”是从行为推测的即时追求，例如避免评价、获得认可、保留安全感。它应作为待检验的解释，不能由应用直接断言。

“内在敌人”是原文使用的隐喻。本项目的正式语义为“阻碍当前方向的内部模式或信念”，包括自我否定，也包括讨好、回避不确定、维护体面等。不得把它缩减为所有问题都来自一个自我否定信念。

归因应同时允许记录技能、资源、时间、机会、身体状态及外部环境。原文强调内部模式，也讨论能动性与机会；不得由此推出“人生停滞从来不是能力或条件不足”。

建议用户追问：“这个行为可能在保护什么？我有什么观察支持这个解释？还有哪些现实条件影响了它？”

## 4. 六组件及相关概念

### 4.1 六组件正式定义

| 组件 | 统一中文名称 | 定义与核心问题 | 来源 |
|---|---|---|---|
| Anti-vision | 反愿景 | 不愿继续体验或走向的生活；现有行为持续后可能产生什么代价？ | S6、S8 |
| Vision | 愿景／愿景 MVP | 当前真正想建设的生活，可在实践中不断完善 | S6、S8 |
| 1 year goal | 一年目标／一年镜头 | 一年后希望成立的一个具体事实，用来判断是否打破旧模式、接近愿景 | S7、S8 |
| 1 month project | 一月项目／一月镜头 | 推进一年目标的阶段项目；需要学习什么、获得什么技能、构建什么成果？ | S7、S8 |
| Daily levers | 每日杠杆 | 优先推进月项目的行动；原文建议为明天的 2–3 个行动安排时间块 | S7、S8 |
| Constraints | 价值约束 | 实现愿景时不愿牺牲的事项与边界，例如健康、重要关系、诚信 | S8 |

身份陈述服务于六组件，但不是用来替换一年目标、月项目或每日杠杆的第七种目标。

### 4.2 目标的具体性与量化

一年目标必须能说明希望观察到的事实。可以是“发布第一件作品”，也可以包含合理的数量、日期或其他指标。原文没有禁止量化结果。

月项目必须解释它如何支持一年目标。仅写“持续成长”“更自律”，不足以表达项目；应补充学习任务、技能或可交付成果。

每日杠杆必须解释它如何推进月项目。执行频次和时长可以用于自我反馈，不用于比较用户价值。

目标可调整不等于任意改写以回避反馈。修改时建议记录新证据、资源变化、方向变化或原先假设的问题。这一修改记录机制属于产品扩展。

产品可以继续禁止排行榜、连签惩罚和羞辱式考核；这类体验约定不等于禁止用户观察成果、使用数值或查看进展。

### 4.3 最小启动行动

统一名称：**最小启动行动**。

定义：当每日杠杆难以开始时，把其中一项缩小为当下能启动的动作。它是 ResetSelf 的产品适配，用于降低开始行动的负担。

例如，“写出作品提纲”可以缩小为“打开文档，写下一个标题”。最小启动行动仍需指向对应项目，不以低门槛本身作为唯一价值。

首页只突出一个最小启动行动，是当前产品的聚焦约定。不得宣称原文要求每日永远只能做一个动作，或用这一个动作替代原文 2–3 项每日行动的完整表达。

### 4.4 价值约束与环境避坑规则

二者必须分别命名、分别解释：

| 项目 | 价值约束 | 环境避坑规则 |
|---|---|---|
| 来源 | 原文六组件，S8 | 产品扩展 |
| 回答的问题 | 为了实现愿景，我不愿牺牲什么？ | 哪些场景容易使我偏离？怎样调整环境？ |
| 示例 | 不以长期睡眠不足换取产出；保留重要关系中的相处时间 | 写作时把手机放在另一房间；睡前关闭短视频入口 |
| 使用方式 | 约束项目方案、时间投入和取舍 | 调整日常环境与行为触发条件 |
| 边界 | 不能简化为坏习惯清单 | 不能代替价值边界 |

价值约束可以进一步转成具体规则，但必须保留被保护的价值。例如：“保护睡眠 → 不安排深夜写作”，比单独写“不要熬夜”更能解释取舍。

### 4.5 反愿景与愿景的不同层次

晨间反愿景包含五年、十年及临终等具体探索，晚间反愿景是一句提炼后的表达。晨间愿景包含三年后的具体生活画面，晚间愿景 MVP 是当前方向的一句话。

产品应区分“探索原稿”与“综合结论”，避免用一句话表单冒充完整心理挖掘。原文时间跨度来自具体问题；不得把“三年反愿景”当作对原题的准确复述。

### 4.6 游戏化与心流

原文将愿景比作获胜方向，反愿景比作赌注，一年目标比作任务，月项目比作 Boss 战，每日杠杆比作 quests，价值约束比作规则。

本项目采用这一组织隐喻，不必实现积分、等级或排行榜。原文的每日 quests 应当推进项目，不能全部改写成与项目无关的休闲支线。兴趣、休息和生活体验可作为产品扩展加入，并说明其作用。

原文提到技能与行动机会匹配；不得宣称只要填写六组件就能自动进入心流或必然沉迷于成长。

## 5. 一日流程与产品适配边界

### 5.1 原文流程基线

| 阶段 | 原文建议与内容 | 方法完成时应保留的表达 |
|---|---|---|
| 准备 | 留出一整天；准备纸笔和开放心态；自主思考 | 给探索、观察和综合留出空间，不把核心回答外包 |
| 晨间 | 建议留出 15–30 分钟；回答 14 问；暂时答不出可以回来继续 | 不满、抱怨、行为目标、难承认的真相、未来代价、旧身份及社交代价、自我保护、三年愿景、新身份、本周行动 |
| 日间 | 回顾晨间内容；创建含问题的提醒；时间尽量随机且不冲突；六个示例问题及三个追加问题 | 观察真实行为，探索回避、身份保护、生命力与安全感的交换 |
| 晚间 | 综合为何卡住、内部模式、反愿景一句话、愿景 MVP；形成年／月／每日镜头 | 从当天观察形成暂定结论，确定明天行动 |
| 整理 | 将洞见组织成六组件 | 保留组件之间的关系及价值边界 |

晨间 14 问的具体题干以原文 VI 第一部分为准。六个日间示例时点是 11:00、13:30、15:15、17:00、19:30、21:00；它们不是作者规定的唯一日程。

三个追加追问分别探索：不再维护旧身份的他人印象会改变什么；在哪里用生命力交换安全；明天能够成为的新身份最小版本是什么。

### 5.2 “一日”与“24h”

“一日”表示跨晨间、日间和晚间的一整天反思安排，不表示连续清醒工作 24 小时、必须隔绝所有人，或等待计时器满 24 小时才能认定有效。

原文没有规定晨间必须 90 分钟、晚间必须 120 分钟，也没有规定每小时必须进行 3 分钟自省。这些时长和频率来自项目的历史扩展设计，应标明为产品建议或版本安排。

当前界面中的“24h 重构”是产品名称。只有支持晨间探索、日间观察、晚间综合的连续关系，才能描述为完整一日流程；完成连续问卷只能说明完成该版本的问卷。

### 5.3 自主思考与数字记录

原文建议纸笔，并明确不要将晨间沉思外包给 AI。应用内输入、草稿保存、结构化回顾和导出是数字产品适配。

如后续加入 AI，它可以帮助整理用户已写的内容、提出待核对的问题；不得代替用户生成核心动机、愿景和身份并当作用户已完成的思考。整理、追问功能是产品扩展，不能因原文另有 Human 3.0 AI prompts 的介绍就宣称本流程要求 AI 代答。

模板和示例用于降低理解与记录负担，不能承诺“用户无需思考”。

### 5.4 降噪与日间生活

“认知真空”是 ResetSelf 对减少干扰的产品命名。独处、静音、灰度、暂停社交输入和专注模式属于产品扩展或适配。

原文建议通勤、散步等场景中的追问，不能将绝对独处、卸载软件、全日不工作或关闭所有通知写成原文的启动条件。

产品应说明实际支持的降噪能力。仅保存一个降噪开关，不等于已经屏蔽其他应用或系统通知；应保留用户需要的自省提醒。

### 5.5 阶段完成与灵活安排

产品可以设计顺序引导、保存状态和提交校验，但这些是交互机制。字数、停顿时间、按钮点击和计时器只能反映操作，不能证明思考深度或身份改变。

跨日继续、快速问卷和只修改上次回答，均属于产品适配，应标注其与原文一日流程的差异。当前版本已拆分为“晨间 14 问探索原稿 + 晚间 11 问综合结论”两段；晚间向导可定义为“简化综合问卷”，不能称为完整替代晨间挖掘，也不能声称已复刻原文的全部时长与顺序。

应用的首次完成状态表示当前版本要求的资料已经提交，不表示人生修复成功。首次重构期间的日间观察属于重构流程自身；流程已支持在首次重构期间进入日间打断，并可在晚间综合前回顾当天观察，不因“先重构、后运维”的守卫约定而把它遗漏。

## 6. 产品扩展清单

| 项目机制 | 来源分类 | 统一解释 |
|---|---|---|
| 身份库最多 5 条、选择当前聚焦身份 | 产品扩展 | 降低同时关注的负担；原文没有给出 5 条上限 |
| 首页常驻反愿景 | 产品扩展 | 提醒生活方向与代价；原文没有规定首页布局 |
| 一个最小启动行动 | 产品适配 | 当前版本突出启动入口，不能覆盖每日杠杆定义 |
| 晨间 14 问完整引导 | 原文建议，S6 | 逐步引导产生答案；原文建议 15–30 分钟，答不出可稍后补充 |
| 三阶段流程（晨间→日间→晚间） | 产品适配 | 用阶段衔接支持跨时段继续；不强制连续 24 小时 |
| 11 步晚间综合向导 | 产品适配 | 整理核心结论与六组件；不能以提交问卷替代完整探索及行动 |
| 可自定义的六时点提醒 | 原文示例＋产品适配 | 提问和时点有原文依据；时点可在准备区按个人日程调整并按新时点重排，重复排程是产品选择 |
| 通知点击直达对应问题 | 产品扩展 | 把提醒直接连到对应自省问题，减少寻找成本；原文未规定通知形式 |
| 每次自省建议 3 分钟 | 产品扩展 | 建议时长，不能称为原文硬性要求 |
| “成长／逃避”行为标签 | 产品扩展 | 用于初步整理；不能穷尽休息、恢复或现实责任等行为 |
| 每日约 1 分钟身份校验、三种匹配状态 | 产品扩展 | 主观自检入口；不等于客观成果或完整控制论循环 |
| 每周约 10 分钟复盘 | 产品扩展 | 将持续反馈组织为固定节奏；原文未规定这一周期 |
| SOS 安抚、呼吸与回到行动 | 产品扩展 | 帮助暂停和整理当下状态；不是原文规定的诊断或治疗 |
| 年度再次使用一日流程 | 原文建议，S6 | 可每年重新反思；固定重生日、倒计时和自动报告是扩展 |
| 无连签惩罚、无排行榜、无负反馈红点 | 产品扩展 | 已有体验约定；不等于不得记录成果或真实偏差 |
| 首页中枢导航、莫兰迪色系、本地存储与备份 | 产品／工程扩展 | 交互、视觉及数据实现选择 |
| 保留修改、归档及用户选择清空重建 | 产品扩展 | 管理个人记录，不是原文规定的人生重置方式 |

扩展机制应说明它支持哪项方法原则，不用“100% 原版”“原版核心禁忌”包装。

## 7. 效果承诺与文案规范

### 7.1 三个层次必须区分

| 层次 | 可以描述什么 | 不得据此推出什么 |
|---|---|---|
| 功能行为 | 在已验证的版本条件下保存草稿、展示记录、安排提醒 | 数据绝不丢失、所有设备都准时、系统已改变用户心理 |
| 方法目标 | 帮助探索动机、明确方向、降低启动负担、支持反馈调整 | 所有用户必然获得洞见、形成习惯或实现目标 |
| 人生结果 | 用户在实践中记录的具体变化 | 一天改变整个人生、永久无内耗、彻底杜绝反弹 |

原文明确不保证流程对所有人有效。“六个月取得六年进展”“任何目标都能实现”等作者表述，应作为原文中的观察或主张介绍，不得作为 ResetSelf 的结果承诺。

### 7.2 统一替换表

| 历史表述 | 问题 | 采用表述 |
|---|---|---|
| 不靠意志力，用身份自动变好 | 暗示自动生效且无需实践 | 从想成为的人出发，让行动更有方向 |
| 所有自律失败都是身份没更新 | 单一原因覆盖所有情况 | 反复偏离时，可以检视身份、动机、方法和现实条件 |
| 表层目标无效，放弃所有结果目标 | 与年目标、月项目及反馈要求冲突 | 让具体目标服务于愿景与生活方式，并允许调整 |
| 年度只定方向，不量化结果 | 把产品偏好误作原文要求 | 用一个具体事实描述一年后的变化，可使用合适指标 |
| 先改身份，反向必反弹 | 将优先关注变成绝对因果禁令 | 将身份与生活方式的反思和行动实践相互连接 |
| 约束就是避坑机制 | 混淆价值边界与环境策略 | 价值约束和环境避坑规则分别定义 |
| 全天隔绝是原版硬性前提 | 原文未规定 | 可减少干扰，并按日程安排自省提醒 |
| 强制 90／120 分钟、每小时 3 分钟 | 将扩展时长冒充原文 | 这是产品建议；原文晨间建议 15–30 分钟，日间时间可调整 |
| 一次重构永久固化新身份 | 忽略持续实践与身份演化 | 将本次方向带入实践，并持续观察和修改 |
| 所有问题都归给旧惯性 | 应用未经观察即替用户归因 | 旧惯性是一种可能解释，也应检查其他影响因素 |
| 偏差不是失败，所以不必看结果 | 混淆不羞辱与不评价方法 | 真实记录结果，用于调整方法，不用于否定个人价值 |
| 彻底终结内耗、杜绝反弹 | 无依据的结果保证 | 支持识别偏离、调整方法和重新开始 |
| 全球唯一、100% 落地原版 | 缺少市场证据及完整实现依据 | 基于 Dan Koe 文章设计，并加入低负担实践机制 |
| 完成重构，人生已重置 | 把操作完成等同于人生结果 | 本次问卷已保存；接下来通过行动检验并调整方向 |

### 7.3 可直接使用的文案

产品介绍：

> 用提问看清动机，用行动检验方向。

方法说明：

> 这套流程帮助你探索想要的生活，并把方向整理成可以实践的目标与行动。改变需要在后续生活中持续尝试，效果因人和条件而异。

目标输入：

> 一年后，希望有什么具体事实成立，让你看见自己正在接近想要的生活？

价值约束输入：

> 为了实现这个愿景，你不愿牺牲什么？这些边界会怎样影响你的选择？

环境避坑输入：

> 哪些场景容易让你偏离？你可以怎样调整环境，让开始行动更容易？

最小启动行动输入：

> 从一项推进月项目的行动中，选出现在能够开始的最小一步。

偏离反馈：

> 记录这次偏离发生的情况，看看下一次可以调整什么。

完成反馈：

> 本次反思已保存。接下来，在生活中尝试这些行动，再根据反馈调整。

以上文案是产品表达，不应标注为作者原话。

## 8. 反馈循环与完整表达标准

### 8.1 方法上的反馈循环

本项目采用如下循环：

1. 明确当前方向及希望发生的具体变化。
2. 选择推进项目的行动，并考虑价值约束及现实条件。
3. 执行行动，记录实际发生的情况。
4. 比较观察到的变化与当前目标，检视原先解释是否成立。
5. 调整行动、环境、项目或目标，再次尝试。

此循环依据 S5；记录模板、修改历史和复盘周期属于产品扩展。

建议的产品记录模板是：“尝试了什么 → 发生了什么 → 得到什么认识 → 下一次调整什么”。只统计打开次数、自省次数、专注次数或主观匹配次数，不足以证明完整反馈循环。

### 8.2 心智与框架觉察

原文的九个心智阶段可作为背景阅读，帮助用户发现自己的观点和身份受语境塑造。不得把这些描述直接当成测评量表、智商分数或用户等级。

原文对“智力”的定义有特定语境，产品宜使用“学习与调整能力”描述相关练习，不使用“你低智力”等评价。无需为表达原文建立心智排行榜。

### 8.3 对“完整表达”的判定

只有在方法内容和用户流程覆盖后，才可描述“完整表达指定原文的核心方法”。至少需核对：

- 身份、生活方式、隐藏目标、身份防御及框架可调整性均有内容支持。
- 晨间 14 问得到完整引导，具体探索原稿与晚间结论能区分。
- 日间六问及追加三问可使用，能回顾晨间内容与实际行为。
- 晚间依据当天观察综合内部模式、反愿景和愿景，并形成行动方向。
- 六组件含义准确；价值约束与避坑规则、每日杠杆与最小启动行动不混用。
- 目标、项目、行动和反馈之间存在可解释的关系。
- 来源、适配差异及效果边界能够被识别。

这是内容与流程标准，不是验证人生改变有效性的标准。
